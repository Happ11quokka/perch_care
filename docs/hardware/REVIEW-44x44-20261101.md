# PerchCare 44×44 기판 교차 검토 (2026-11-01)

대상: `PerchCare-44x44-REVIEW-DRAFT-20261101/` (번들·원본 ZIP은 로컬 `체중기/`에만 보관 — git 미포함)
방법: KiCad 원본(.kicad_pcb / .kicad_sch / 라이브러리)을 직접 파싱해 BOM·CPL·expected-nets·review 문서와 대조하고, TI 데이터시트(TPS61099, BQ24073, TLV7032, TPS63020)와 정수 계산을 확인했다.
한계: 이 머신에 KiCad가 없어서 ERC/DRC를 다시 돌리지는 않았다(번들의 `drc.json` 결과를 그대로 신뢰). Gerber 렌더링, STEP 간섭, JLC 실물 회전 미리보기도 하지 않았다.

## 2. 발견 사항

### H1. J3 부품 정체가 문서마다 다름 — 높음
- BOM/CPL: `1125R-SMT-4P`, LCSC 칸이 비어 있음
- assembly-requirement.json: MPN `1125R-SMT-4P`, Seeed SKU `320110032`
- PCB footprint와 README: `Seeed 114020164` / `C604849`
- 회로도 필드 CandidateSupplierPart: `DigiKey 1597-114020164-ND`

같은 J3에 두 계열의 부품번호가 섞여 있다. footprint(`Grove_114020164_PHS4AW_review`)는 114020164 도면을 기준으로 만들었으니, **BOM 행과 assembly 문서를 114020164로 통일하거나 1125R로 정리**해야 한다. 정리하지 않으면 다음 견적이나 수동 납땜 때 엉뚱한 부품을 살 위험이 있다.
→ 제안: JLC 재고가 0이니, 이번 2장은 J3를 빼고 조립한 뒤 손으로 납땜하는 쪽이 현실적이다. 신호 패드 1.0×3.4 mm, 피치 2.0 mm라 손납땜이 쉽다. 이 방법을 쓰면 BOM에서 J3를 DNP로 명시해 두는 게 좋다.

### H2. VBUS 과전압 내성은 사실상 7 V — 중간~높음
BQ24073의 IN은 28 V까지 버티지만, **VBUS에 바로 연결된 다른 부품들의 절대최대가 7 V**다.
- U7 TLV7032 VCC (abs max 7 V)
- BQ24073 /CE (R34 47k로 VBUS에 풀업, abs max 7 V)
- 기준 분압기와 NTC 풀업도 VBUS에 직결

USB-C를 꽂는 순간 생기는 링잉이나 불량 충전기가 들어오면 충전기는 살아남아도 온도 창 회로가 먼저 망가질 수 있다. PHY09에 "VBUS surge"가 이미 있긴 하지만, 실측하기 **전에 설계로 막는 편이 싸다**.
→ 제안 중 하나: (a) VBUS에 5 V급 TVS를 추가한다(그래도 클램프 전압이 7 V를 넘을 수 있으니 b와 함께 쓰는 게 좋다). (b) U7, R29–R34에 들어가는 전원을 VBUS에서 직렬 저항과 5.1–5.6 V 제너로 클램프한 `VBUS_SNS` 레일로 바꾼다. 비율식 구조라 기준점이 같이 움직이므로 임계 온도는 유지된다.

### M1. U4 paste가 mask 밖으로 나가는 원인 — 중간 (원인은 확인됨, 수정은 간단)
TI 예시와 크기는 같고, **모서리 반경만 다르다**. EP 구리·mask는 `roundrect_rratio 0.1`이라 반경 0.10 mm, paste 개구는 1.0×0.7에 같은 비율이 적용돼 반경 0.07 mm다. paste 바깥 가장자리가 mask 가장자리와 정확히 겹쳐서, 반경이 작은 paste 모서리 4곳이 mask 모서리 밖으로 몇 µm 나간다. 보고된 범위(x 13.5–14.5, y 20.4–22.0)는 정확히 U4 EP다.
실물에 미치는 영향은 무시할 만하지만, DFM 결과에 fail로 남아 있으니 고친다. 다음 중 하나를 고르면 된다.
1. U4 패드 7(그리고 신호 패드)에 `solder_mask_margin 0.05`를 준다. TI가 권장하는 NSMD 방식(개구는 구리보다 최대 0.07 mm 크게)과도 맞는다. 프로젝트 전역 `pad_to_mask_clearance`가 0이라 지금은 사실상 개구 = 구리 크기다.
2. 또는 paste 패드를 `roundrect_rratio 0.0714`(반경 0.05, TI 예시 R0.05)로 바꾼다.

1번을 권한다. 고친 뒤에는 Gerber를 다시 export하고 `gerber-no-macros-inspection`을 다시 돌려야 한다.

### M2. ILIM 3.09k는 USB 기본 500 mA를 살짝 넘음 — 중간(펌웨어로 피할 수 있음)
EN2=1, EN1=0으로 두면 입력 한도 = KILIM/3.09k = **485–557 mA**(typ 521)가 된다. Rd 5.1k만 있는 USB-C 기본 전원은 500 mA를 보장할 뿐이다.
→ 펌웨어에서 **USB500 모드(EN2=0, EN1=1)**를 쓰거나, R6를 3.4k 이상(최대 ≤473 mA)으로 바꾼다. programming 문서의 "500 mA를 일괄 적용하지 말 것" 원칙과 같은 맥락이니 문서에 한 줄 추가해 둔다.

### M3. CPL 회전 보정 0 → JLC 미리보기에서 꼭 확인할 부품
CPL은 KiCad 회전값을 그대로 내보냈고, 극성이 있는 부품이 전부 자체 footprint다. 아래 부품은 JLC 3D 미리보기에서 pin1이나 극성을 하나씩 확인해야 한다(SOT-23과 QFN/SON은 JLC 라이브러리 기준 각도가 KiCad와 90°나 180° 다른 경우가 흔하다).

| Ref | 패키지 | KiCad 회전 | pin1 위치(footprint 좌표) |
|---|---|---|---|
| U1 | WROOM-02 | 0 | 좌상단 (-8.75, -2.9) |
| U2 | VQFN-16 RGT | 0 | 좌상단 |
| U3 | DSJ-14 | 0 | 좌상단 |
| U4 | WSON-6 DRV | 0 | 좌상단 |
| U7 | WSON-8 DSG | 0 | 좌상단 |
| Q1, Q2 | SOT-23 | 0 | 좌상단 (-1.0, -0.95) |
| D1 | DRT-3 | 0 | 좌상단 |
| D2 | LED 0805 | 0 | 캐소드 = 패드 1 (-0.95, 0) |
| J1 | USB-C | 90 | — (입구가 오른쪽 끝을 향하는지 확인) |
| J2 | JST PH SM4 | 0 | pin1 = +X 쪽 |

J2는 KiCad 공식 `JST_PH_B3B-PH-SM4-TB`와 비교했다. 공식 footprint는 pin1이 -X, MP가 -Y에 있고, 이 footprint는 그것을 180° 돌린 것과 같다(pin1 +X, MP +Y). **좌우가 뒤집힌 것은 아니어서 극성 방향은 일관된다.** 다만 JLC 회전값은 이 180° 차이를 반영해 확인해야 한다. 배터리를 반대로 꽂으면 치명적이니 J2는 미리보기에서 MP 방향까지 반드시 본다.

### L1. PCB 비용 — 0.2 mm 드릴 비아가 104개 중 79개
견적의 MinVia $16.78, Plugged via $16.56, Kelvin test $16.67는 0.2 mm 드릴 때문에 자동으로 붙었을 가능성이 높다. 셋을 합치면 PCB 5장 $70.81 중 약 $50이다. 프로젝트 기본값은 0.7/0.3인데, 실제로는 0.6/0.2와 0.7/0.2가 대부분이다. 44×44 양면 기판에 여유가 있으니, QFN/DSJ 팬아웃처럼 꼭 필요한 곳만 남기고 0.3 드릴로 바꾸면 PCB 비용이 크게 줄 수 있다. 바꾼 뒤에는 JLC에서 다시 견적을 받아 확인해야 한다.

### L2. 기타
- **Grove 라인 ESD**: I2C_SCL/SDA가 외부 케이블에서 100 Ω만 거쳐 ESP32로 들어간다. 저용량 ESD 다이오드 어레이(2–4ch)를 J3 가까이 두는 것을 검토할 만하다.
- **SENSOR_5V 단락**: TPS61099가 단락 시 200 mA로 제한하고 shutdown 시 부하를 끊는다(데이터시트 확인). 케이블이 단락돼도 보호된다.
- **J1 입구가 기판 끝(x=44)과 같은 높이**: 케이스 벽 두께만큼 플러그가 덜 들어간다. 케이스를 설계할 때 벽을 얇게 하거나 0.3–0.6 mm 튀어나오게 할지 결정해야 한다(문서의 "커넥터 체결 따로 확인"과 같은 항목).
- **J2 팩 핀 순서**(BAT+, NTC, GND)가 시중 3선 팩과 다를 수 있다. 하네스를 주문 제작해야 한다는 점이 문서에 이미 있다.
- **verification.json의 "all_75_footprints"**: BOM 67 + TP 5 + FID 3 = 75로 맞는다(불일치 아님).
- **CHG_N이 IO20(U0RXD)에 연결**: ROM 부팅 중 UART RX에 충전 상태 신호가 들어가지만 실사용 영향은 거의 없다. programming 문서에 TP1을 UART_RX로 쓰지 말라고 이미 적혀 있다.
